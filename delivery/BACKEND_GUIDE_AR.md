# دليل فريق الباك-اند — اختبار وربط خدمة تقييم التلاوة (Quran-ARS)

> هذا الملف يشرح **ما المطلوب من فريق الباك-اند** لاختبار الخدمة وربطها بتطبيقكم.
> كل ما تحتاجونه موجود داخل مجلد `delivery/`. لا تحتاجون أي شيء إضافي من فريق الذكاء الاصطناعي.

---

## ١) ما هي الخدمة باختصار

خدمة ذكاء اصطناعي تستقبل **تسجيلاً صوتياً** لتلاوة قرآنية، وتُرجِع:

- **درجة الحفظ** — هل تلا الطالب الكلمات الصحيحة بالترتيب (كلمات صحيحة / خاطئة / ناقصة).
- **التلاوة بالتشكيل** — نصّ ما نطقه الطالب **فعلاً** بالحركات (وليس النص الصحيح — أي تُظهر تلاوته الحقيقية).
- **أخطاء التجويد/الحركات** — مثلاً: نطق **ضمة** مكان **كسرة** في حرف معيّن.

كل ذلك عبر نقطة نهاية **غير متزامنة (async)**: ترسلون الطلب، تحصلون فوراً على `jobId`،
ثم تصلكم النتيجة الكاملة على **رابط ويبهوك (webhook)** تحدّدونه أنتم.

---

## ٢) المتغيّر الوحيد الذي يجب أن يتطابق: `AI_API_KEY`

هذا هو **السرّ المشترك الوحيد** بين الطرفين:

- الخدمة تُشغَّل بقيمة `AI_API_KEY`.
- **كل** طلب إلى `/api/evaluate` يجب أن يحمل الترويسة: `X-AI-API-Key: <AI_API_KEY>` بنفس القيمة (القيمة مباشرة، بدون `Bearer`). ترويسة `Authorization` محجوزة لبوابة RunPod Serverless نفسها.
- إذا اختلفت القيمتان ← يكون الرد **401** (`AUTH_FAILED`).

> في اختبار كولاب (Colab) القيمة هي `test-key-123`. في الإنتاج تختارون أنتم قيمة قوية وتستخدمونها في الطرفين.

باقي القيم (`webhookSecret`, `audioUrl`, `surahNumber`, ...) **ترسلونها أنتم داخل كل طلب** — ليست أسراراً مشتركة مسبقاً.

---

## ٣) أسهل طريقة للاختبار الآن (قبل شراء السيرفر)

عند تشغيل نوتبوك كولاب `delivery/Colab_Test.ipynb` تظهر في **الخطوة ٣** عنوان عام مثل:
`https://xxxx.trycloudflare.com` — هذا **رابط حيّ للخدمة**. اختبروا هكذا:

**١.** افتحوا موقع **https://webhook.site** وانسخوا الرابط الخاص بكم (يلتقط أي POST ويعرضه فوراً).

**٢.** أرسلوا الطلب (عبر `curl` أو Postman) إلى الرابط العام:

```bash
curl -X POST https://xxxx.trycloudflare.com/api/evaluate \
  -H "X-AI-API-Key: test-key-123" \
  -H "Content-Type: application/json" \
  -d '{
    "audioUrl": "https://everyayah.com/data/Husary_128kbps/112002.mp3",
    "surahNumber": 112, "surahName": "الإخلاص",
    "fromAyah": 2, "toAyah": 2,
    "userId": 1, "recitationId": 1,
    "webhookUrl": "https://webhook.site/YOUR-UNIQUE-ID",
    "webhookSecret": "any-test-secret"
  }'
```

**٣.** ستحصلون فوراً على: `{"status":"processing","jobId":"..."}`، وبعد ثوانٍ تظهر **النتيجة الكاملة** في
صفحة webhook.site (كائن `data` يحتوي الدرجة، والتلاوة بالتشكيل، وأخطاء الحركات).

> هكذا تختبرون **العقد بالكامل** مقابل خدمة كولاب المجانية. عند الإنتاج، الشيء الوحيد الذي يتغيّر هو
> استبدال الرابط العام برابط السيرفر الحقيقي.

---

## ٤) شروط مهمّة لنجاح الاختبار

- **`audioUrl`** يجب أن يكون رابطاً **عامّاً** يستطيع السيرفر تنزيله (روابط `everyayah`، أو تخزينكم السحابي/‏CDN).
- **`webhookUrl`** يجب أن يكون **عامّاً** يستطيع السيرفر الوصول إليه:
  - للتجربة: استخدموا `https://webhook.site`.
  - للربط الحقيقي: ضعوا نقطة نهاية الباك-اند الحقيقية. وإن كانت على جهاز محلي (localhost)، استخدموا نفقاً مثل **ngrok**.
- **الترويسة**: `X-AI-API-Key: <AI_API_KEY>` بنفس قيمة مفتاح الخدمة.

---

## ٥) شكل الطلب — `POST /api/evaluate`

الترويسات: `X-AI-API-Key: <AI_API_KEY>` و `Content-Type: application/json`.

الحقول (JSON):

| الحقل | النوع | الوصف |
|---|---|---|
| `audioUrl` | string | رابط عام للتسجيل الصوتي (يقوم السيرفر بتنزيله). **مطلوب** |
| `surahNumber` | int | رقم السورة. **مطلوب** |
| `surahName` | string | اسم السورة (اختياري، للعرض). |
| `fromAyah` | int | أول آية في المقطع المطلوب. **مطلوب** |
| `toAyah` | int | آخر آية في المقطع. **مطلوب** |
| `userId` | int | معرّف المستخدم (يُعاد كما هو). |
| `recitationId` | int | معرّف التلاوة (يُعاد كما هو). |
| `webhookUrl` | string | الرابط الذي تصله النتيجة. **مطلوب** |
| `webhookSecret` | string | سرّ تختارونه؛ يُعاد في ترويسة الويبهوك لتتحقّقوا منه. |

**الرد الفوري** (خلال ثانيتين):

```json
{ "status": "processing", "jobId": "…", "estimatedTime": 30 }
```

---

## ٦) شكل رد الـ Webhook (النتيجة النهائية)

يرسل السيرفر طلب `POST` إلى `webhookUrl` مع الترويسة `Authorization: Bearer <webhookSecret>`، وجسمه:

```json
{
  "jobId": "…",
  "recitationId": 1,
  "userId": 1,
  "status": "success",
  "data": {
    "overallScore": 87.5,
    "passed": true,
    "totalWords": 4, "correctWords": 4, "incorrectWords": 0,
    "userRecitation": "…",
    "userRecitationDiacritized": "…",
    "expectedRecitation": "…",
    "harakatChecked": 4,
    "harakatErrors": [
      { "word": "دِينَكُمْ", "expectedWord": "دِينُكُمْ",
        "details": [ { "letter": "ن", "got": "fatha", "expected": "damma" } ] }
    ],
    "words": [
      { "word": "…", "expected": "…", "isCorrect": true, "score": 1.0,
        "errorType": null, "errorTypeAr": null, "charErrors": [],
        "timestampStart": null, "timestampEnd": null }
    ],
    "errors": ["…ملاحظات بالعربية…"],
    "feedbackAudio": "https://<عنوان-الخدمة>/audio/feedback_<jobId>.mp3",
    "referenceAudio": "https://everyayah.com/...mp3",
    "modelVersion": "namaa-cohere-speech-tashkeel-2b"
  }
}
```

- **المفاتيح العليا ثابتة**: `jobId, recitationId, userId, status, data` (ويُضاف `message` عند الخطأ).
- في حالة الفشل: `{ "…", "status": "error", "message": "…" }`.
- عند فشل التسليم يُعاد المحاولة ٣ مرات (١ث ← ٢ث ← ٤ث) عند أخطاء 5xx/انتهاء المهلة فقط.
- **أهم الحقول للعرض في التطبيق**: `overallScore` (٠–١٠٠)، `passed`، `userRecitationDiacritized`
  (تلاوة الطالب بالتشكيل)، و `harakatErrors` (أخطاء الحركات).

---

## ٧) ملاحظات تشغيلية

- **الاحتفاظ بالصوت التوضيحي**: ملفات `feedback_*.mp3` تُخدَّم على `/audio/`. احتفظوا بها **٣٠ يوماً على الأقل** —
  لا تحذفوها بمهمة تنظيف مؤقتة.
- **الشبكة**: تأكّدوا أن السيرفر يستطيع (أ) تنزيل `audioUrl`، و(ب) الوصول إلى `webhookUrl`،
  و(ج) أن `PUBLIC_BASE_URL` هو العنوان الذي يصل منه تطبيقكم إلى ملفات الصوت.
- **الصحة**: `GET /health` يُعيد `{"status":"ok","model_loaded":true}` — اربطوه بموازِن الأحمال.
- **المصادقة**: أي طلب بدون الترويسة الصحيحة يُرَدّ بـ 401.

---

## ٨) عند الانتقال للإنتاج (بعد شراء السيرفر)

نفس الخطوات تماماً، لكن:
- بدل الرابط العام المؤقت (كولاب) ← رابط السيرفر الحقيقي عبر HTTPS.
- يُبنى ويُشغَّل من مجلد `delivery/` عبر: `docker compose up -d --build`
  (النموذج مُضمَّن داخل الصورة، فلا حاجة لإنترنت وقت التشغيل).
- تُضبط قيمتا البيئة: `AI_API_KEY` و `PUBLIC_BASE_URL`.

**مراجع كاملة داخل نفس المجلد:**
- `AGENT_DEPLOY_PROMPT.md` — تعليمات النشر الكاملة (يمكن تسليمها لوكيل/مطوّر DevOps مباشرة).
- `BACKEND_HANDOFF.md` — العقد الكامل للـ API وقائمة القبول.
- `DEPLOYMENT_GUIDE.md` — تفاصيل السحابة و Nginx و systemd والتكلفة.
- `Colab_Test.ipynb` — اختبار مجاني كامل على GPU قبل شراء السيرفر.

---

## ٩) خلاصة ما على الباك-اند فعله الآن

1. الحصول من فريق الذكاء الاصطناعي على: **الرابط العام** (من كولاب) وقيمة **`AI_API_KEY`** (`test-key-123` للتجربة).
2. تجهيز رابط **webhook** عام (الأسهل: `webhook.site`).
3. إرسال طلب `POST /api/evaluate` كما في القسم ٣، والتأكّد من وصول النتيجة على الويبهوك.
4. قراءة الحقول من `data` وعرضها في التطبيق (الدرجة، التلاوة بالتشكيل، أخطاء الحركات).
5. عند الجاهزية للإنتاج: نشر الخدمة من `delivery/` على سيرفر GPU، وتبديل الرابط بالرابط الحقيقي.
